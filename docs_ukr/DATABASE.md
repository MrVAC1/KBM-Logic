# Документація Інтеграції з Базою Даних

## Огляд

Додаток використовує **MongoDB Atlas** (хмарний MongoDB) як основну базу даних. Цей документ описує підключення до бази даних, структуру схеми та ключові моделі.

---

## Підключення MongoDB Atlas

### Конфігурація

**Рядок Підключення:** Встановлено в `server/.env`
```env
MONGODB_URI=mongodb+srv://username:password@cluster0.xxx.mongodb.net/kbm-logic?retryWrites=true&w=majority&appName=Cluster0
```

**Назва Бази Даних:** `kbm-logic`

**Опції Підключення:**
- `serverSelectionTimeoutMS: 10000` (10 секунд)
- `socketTimeoutMS: 45000` (45 секунд)
- `retryWrites: true` (потрібно для реплікаційних наборів Atlas)
- `w: 'majority'` (гарантія запису для Atlas)

**Файл Підключення:** `server/config/db.js`

### Потік Підключення

1. Завантажити `MONGODB_URI` з змінних середовища
2. Перевірити існування рядка підключення
3. Попереджати, якщо використовується локальний MongoDB (слід використовувати Atlas)
4. Підключитися з оптимізованими опціями
5. Обробляти події підключення (помилка, відключення, повторне підключення)

## Ключові Моделі

### 1. Модель Проекту

**Колекція:** `projects`

**Ключові Поля:**

| Поле | Тип | Опис |
|------|-----|------|
| `name` | String (обов'язково) | Назва проекту |
| `description` | String | Опис проекту |
| `ownerId` | ObjectId (обов'язково, індексовано) | Посилання на User (власник проекту) |
| `deadline` | Date (nullable) | Цільова дата завершення ⭐ |
| `createdAt` | Date (автоматично) | Дата створення проекту |
| `workSchedule` | Object | Конфігурація робочого графіка |
| `members[]` | Array | Члени проекту з ролями та дозволами |
| `customRoles[]` | Array | Визначення кастомних ролей |
| `fixedCosts[]` | Array | Елементи фіксованих витрат |
| `evmSnapshots[]` | Array | Кешовані знімки розрахунків EVM |
| `isDeleted` | Boolean | Прапорець м'якого видалення |

**Структура Робочого Графіка:**
```javascript
{
  workingDaysPerWeek: Number,  // 1-7
  daysOffPerWeek: Number,       // 0-6
  hoursPerDay: Number           // 1-24
}
```

**Структура Члена:**
```javascript
{
  userId: ObjectId,            // Посилання на User
  roles: [String],            // Масив назв ролей
  permissions: [String],      // Масив рядків дозволів (enum: ALL_PERMISSIONS)
  hourlyRate: Number,
  joinedAt: Date,
  notificationSettings: {
    notifyOnTaskAssignment: Boolean,
    notifyOnBudgetRisk: Boolean,
    // ... інші налаштування сповіщень
  }
}
```

**Структура Кастомної Ролі:**
```javascript
{
  name: String,                // Назва ролі
  color: String,              // Колір відображення
  hierarchy: Number,         // Позиція в ієрархії
  permissions: [String]      // Масив рядків дозволів
}
```

**Структура Знімка EVM:**
```javascript
{
  date: Date,                // Дата знімка
  plannedValue: Number,      // PV для цієї дати
  actualCost: Number,        // AC для цієї дати
  earnedValue: Number       // EV для цієї дати
}
```

**Індекси:**
- `{ ownerId: 1, isDeleted: 1 }` - Знайти проекти за власником
- `{ inviteCode: 1 }` - Знайти проекти за кодом запрошення

### 2. Модель Транзакції

**Колекція:** `transactions`

**Ключові Поля:**

| Поле | Тип | Опис |
|------|-----|------|
| `projectId` | ObjectId (обов'язково, індексовано) | Посилання на Project |
| `amount` | Number (обов'язково) | Сума транзакції |
| `type` | Enum: '+', '-' (обов'язково) | '+' = Дохід, '-' = Витрата |
| `source` | String (обов'язково) | Джерело транзакції |
| `date` | Date (обов'язково, незмінно, індексовано) | Дата транзакції |
| `authorId` | ObjectId (обов'язково) | Посилання на User (створювач) |
| `description` | String | Опис транзакції |
| `createdAt` | Date (автоматично) | Мітка часу створення |
| `updatedAt` | Date (автоматично) | Мітка часу оновлення |

**Використання в EVM:**
- **Дохід (`type: '+'`):** Збільшує доступний бюджет
- **Витрата (`type: '-'`):** Збільшує Фактичну Вартість (AC)

**Індекси:**
- `{ projectId: 1, type: 1, date: -1 }` - Оптимізовано для розрахунку бюджету
- `{ projectId: 1, date: -1 }` - Загальний пошук транзакцій
- `{ projectId: 1, type: 1 }` - Транзакції за типом

---

### 3. Модель Задачі

**Колекція:** `tasks`

**Ключові Поля:**

| Поле | Тип | Опис |
|------|-----|------|
| `projectId` | ObjectId (обов'язково, індексовано) | Посилання на Project |
| `title` | String (обов'язково) | Назва задачі |
| `description` | String | Опис задачі |
| `status` | Enum (індексовано) | 'Todo', 'In Progress', 'Review', 'Done' |
| `priority` | Enum | 'Low', 'Medium', 'High', 'Critical' |
| `complexity` | Enum | 'Low', 'Med', 'High' |
| `assignees[]` | Array of ObjectId | Посилання на User |
| `startDate` | Date | Дата початку задачі |
| `deadline` | Date | Дедлайн задачі |
| `estimateHours` | Number (обов'язково, min: 0) | Оцінка годин для завершення |
| `plannedValue` | Number | Автоматично розрахована запланована вартість |
| `plannedCost` | Number | Автоматично розрахована запланована вартість |
| `risk` | Object | Дані оцінки ризику |
| `updatedAt` | Date (індексовано) | Мітка часу останнього оновлення (використовується для розрахунку EV) |

**Структура Ризику:**
```javascript
{
  probability: Number,      // 1-5
  impact: Number,          // 1-5
  auto_score: Number,      // Розрахована оцінка ризику
  isAutoAdjusted: Boolean,
  autoAdjustReason: String
}
```

**Індекси:**
- `{ projectId: 1, status: 1, updatedAt: -1 }` - Оптимізовано для розрахунку EV
- `{ projectId: 1, status: 1 }` - Загальний пошук задач проекту
- `{ assignees: 1 }` - Знайти задачі за виконавцем
- `{ deadline: 1 }` - Знайти задачі за дедлайном

---

### 4. Модель Витрат

**Колекція:** `expenses`

**Ключові Поля:**

| Поле | Тип | Опис |
|------|-----|------|
| `projectId` | ObjectId (обов'язково, індексовано) | Посилання на Project |
| `name` | String (обов'язково) | Назва витрати |
| `amount` | Number (обов'язково, min: 0) | Сума витрати |
| `frequency` | Enum | 'daily', 'weekly', 'monthly', 'yearly' |
| `createdBy` | ObjectId (обов'язково) | Посилання на User (створювач) |
| `updatedBy` | ObjectId | Посилання на User (останній оновлювач) |
| `createdAt` | Date (індексовано) | Мітка часу створення |
| `updatedAt` | Date | Мітка часу оновлення |

**Використання в EVM:**
- Вносить внесок у розрахунок Фактичної Вартості (AC)
- Розрахунок на основі частоти:
  - Щоденно: `сума × дніВідПочатку`
  - Щотижня: `сума × ceil(дніВідПочатку / 7)`
  - Щомісяця: `сума × ceil(дніВідПочатку / 30.44)`
  - Щороку: `сума × ceil(дніВідПочатку / 365)`

**Індекси:**
- `{ projectId: 1, createdAt: 1, frequency: 1 }` - Оптимізовано для розрахунку AC
- `{ projectId: 1, createdAt: -1 }` - Загальний пошук витрат

---

### 5. Модель Користувача

**Колекція:** `users`

**Ключові Поля:**

| Поле | Тип | Опис |
|------|-----|------|
| `firebaseUid` | String (унікальний, індексовано) | Firebase Authentication UID |
| `email` | String (унікальний) | Email адреса користувача |
| `displayName` | String | Відображуване ім'я користувача |
| `photoURL` | String | URL фото профілю користувача |
| `monthlySalary` | Number | Місячна зарплата (використовується для розрахунків ставок) |
| `createdAt` | Date (автоматично) | Дата створення облікового запису |
| `updatedAt` | Date (автоматично) | Мітка часу останнього оновлення |

**Використання в EVM:**
- `monthlySalary` використовується для розрахунку:
  - Годинна ставка: `Місячна Зарплата / Робочі Години на Місяць`
  - Денна ставка: `Місячна Зарплата / Робочі Дні на Місяць`

## Зв'язки Бази Даних

### Проект → Члени → Користувачі
```
Project.members[].userId → User._id
```

### Проект → Задачі
```
Task.projectId → Project._id
```

### Проект → Транзакції
```
Transaction.projectId → Project._id
Transaction.authorId → User._id
```

### Проект → Витрати
```
Expense.projectId → Project._id
Expense.createdBy → User._id
```

### Задача → Виконавці → Користувачі
```
Task.assignees[] → User._id
```

## Потік Даних для Розрахунків EVM

### PV (Запланована Вартість)
1. Запит колекції `Task`: `{ projectId: projectId }`
2. Заповнити `assignees` з `User.monthlySalary`
3. Розрахувати бюджети задач з `estimateHours` та годинних ставок
4. Сумувати на основі дедлайнів задач та цільової дати

### AC (Фактична Вартість)
1. Запит `Project.members[]` → Отримати `User.monthlySalary`
2. Розрахувати денні ставки з зарплат
3. Запит колекції `Expense`: `{ projectId: projectId }`
4. Запит колекції `Transaction`: `{ projectId: projectId, type: '-', date: { $lte: цільоваДата } }`
5. Сума: Зарплати + Витрати + Негативні Транзакції

### EV (Зароблена Вартість)
1. Запит колекції `Task`: `{ projectId: projectId, status: 'Done', updatedAt: { $lte: цільоваДата } }`
2. Заповнити `assignees` з `User.monthlySalary`
3. Розрахувати бюджети задач для завершених задач
4. Сума всіх бюджетів завершених задач

### Розрахунок Бюджету
1. Розрахувати PV (див. вище)
2. Запит колекції `Transaction`: `{ projectId: projectId, type: '+' }`
3. Сума позитивних транзакцій
4. Розрахунок: `Залишковий Бюджет = (PV + Доходи) - AC`

## Оптимізації Продуктивності

### Індекси
Всі моделі мають оптимізовані індекси для загальних шаблонів запитів:
- Пошук проектів за власником
- Запити задач за проектом та статусом
- Запити транзакцій за проектом, типом та датою
- Запити витрат за проектом та датою

### Кешування Знімків
- Історичні значення EVM кешовані в `Project.evmSnapshots[]`
- Зменшує час перерахунку на ~90% для історичних дат
- Щоденна cron-задача оновлює знімки

### Оптимізація Запитів
- Використовувати `.lean()` для запитів тільки для читання (швидше)
- Використовувати `.populate()` тільки коли потрібно
- Фільтрувати на рівні бази даних, а не в коді додатку

## Скрипти Міграції

### Очищення Дозволів
```bash
npm run cleanup:permissions
```
Видаляє застарілі дозволи (`can_track_time`) з усіх проектів.

### Виправлення Дозволів Дедлайну
```bash
npm run fix:deadline-permissions
```
Додає `can_manage_deadline` до ролей Власника та Менеджера Проекту.

## Усунення Несправностей Підключення

### Проблема: Таймаут Підключення
**Рішення:**
- Перевірити білий список IP MongoDB Atlas
- Перевірити формат рядка підключення
- Перевірити мережеву підключеність

### Проблема: Помилка Аутентифікації
**Рішення:**
- Перевірити ім'я користувача та пароль у рядку підключення
- Перевірити дозволи користувача бази даних в Atlas
- Переконатися, що назва бази даних правильна (`kbm-logic`)

### Проблема: База Даних Не Знайдена
**Рішення:**
- Перевірити назву бази даних у рядку підключення: `...mongodb.net/kbm-logic?...`
- Перевірити, чи існує база даних в Atlas
- Переконатися, що користувач має доступ до бази даних

## Примітки Безпеки

1. **Рядок Підключення:** Ніколи не комітити файл `.env` у систему контролю версій
2. **Облікові Дані:** Зберігати тільки в змінних середовища
3. **Білий Список IP:** Налаштувати білий список IP MongoDB Atlas
4. **Користувач Бази Даних:** Використовувати виділеного користувача бази даних з мінімальними необхідними дозволами

## Резервне Копіювання та Відновлення

### Рекомендована Стратегія Резервного Копіювання
1. **Автоматичні Резервні Копії MongoDB Atlas:** Увімкнути в панелі Atlas
2. **Ручні Експорти:** Використовувати `mongodump` для критичних даних
3. **Частота Знімків:** Рекомендовані щоденні знімки

### Процес Відновлення
1. Відновити з резервної копії Atlas
2. Запустити скрипти міграції, якщо схема змінилася
3. Перевірити цілісність даних
