# Документація EVM Фінансової Логіки

## Огляд

Система управління заробленою вартістю (EVM) надає комплексне фінансове відстеження та аналіз для проектів. Цей документ деталізує основні формули, методи розрахунку та джерела даних.

---

## Основні формули EVM

### 1. Запланована Вартість (PV)

**Визначення:** Бюджетна вартість роботи, запланованої до завершення на певну дату.

**Формула:**
```
PV = Σ (Бюджет Задачі × Відсоток Завершення)
```

**Метод Розрахунку:**
- Для кожної задачі з `estimateHours > 0`:
  - Розрахувати бюджет задачі: `estimateHours × Середня Годинна Ставка`
  - Годинна ставка виводиться з: `Місячна Зарплата / Робочі Години на Місяць`
  - Робочі години на місяць: `(робочіДніНаТиждень × 4.33) × годинНаДень`
- Якщо дедлайн задачі ≤ цільова дата: Додати повний бюджет задачі
- Якщо дедлайн задачі > цільова дата: Розрахувати лінійну денну частину
  - `деннаЧастина = бюджетЗадачі / тривалістьЗадачі`
  - `частковийPV = min(бюджетЗадачі, деннаЧастина × дніВідПочатку)`

**Джерело Істини:**
- Колекція задач (`Task` модель)
- Місячні зарплати користувачів (`User.monthlySalary`)
- Робочий графік проекту (`Project.workSchedule`)

**Оптимізація:**
- Використовує кешовані знімки (`project.evmSnapshots`) для історичних дат
- Перераховує тільки для сьогодні або майбутніх дат

---

### 2. Фактична Вартість (AC)

**Визначення:** Фактична вартість, понесена за виконану роботу на певну дату.

**Формула:**
```
AC = Зарплати + Фіксовані Витрати + Негативні Транзакції
```

**Компоненти Розрахунку:**

#### A. Зарплати (Розрахунок Денної Ставки)
```
Денна Ставка = Місячна Зарплата / Робочі Дні на Місяць
Робочі Дні на Місяць = (робочіДніНаТиждень / 7) × 30.44
AC від Зарплат = Σ (Денна Ставка × Дні Від Приєднання Члена)
```

#### B. Фіксовані Витрати
- З колекції `Expense` (на основі частоти):
  - Щоденно: `сума × дніВідПочатку`
  - Щотижня: `сума × ceil(дніВідПочатку / 7)`
  - Щомісяця: `сума × ceil(дніВідПочатку / 30.44)`
  - Щороку: `сума × ceil(дніВідПочатку / 365)`
- З масиву `Project.fixedCosts` (така ж логіка частоти)

#### C. Негативні Транзакції
- Сума всіх документів `Transaction`, де:
  - `type === '-'` (витрата)
  - `date <= цільоваДата`

**Джерело Істини:**
1. **Зарплати:** `Project.members` → `User.monthlySalary` → Розрахована денна ставка
2. **Фіксовані Витрати:** Колекція `Expense` + масив `Project.fixedCosts`
3. **Негативні Транзакції:** Колекція `Transaction` (`type: '-'`)

**Оптимізація:**
- Використовує кешовані знімки для історичних дат
- Розраховує тільки для сьогодні або майбутніх дат

---

### 3. Зароблена Вартість (EV)

**Визначення:** Бюджетна вартість фактично виконаної роботи на певну дату.

**Формула:**
```
EV = Σ (Бюджет Задачі для Завершених Задач)
```

**Метод Розрахунку:**
- Знайти всі задачі, де:
  - `status === 'Done'`
  - `updatedAt <= цільоваДата` (завершено на або до цільової дати)
- Для кожної завершеної задачі:
  - Розрахувати бюджет задачі: `estimateHours × Середня Годинна Ставка`
  - Додати до загального EV

**Джерело Істини:**
- Колекція задач (`Task` модель)
- Статус задачі та дата завершення (`Task.status`, `Task.updatedAt`)

**Оптимізація:**
- Використовує кешовані знімки для історичних дат
- Розраховує тільки для сьогодні або майбутніх дат

---

### 4. Відхилення Графіка (SV)

**Формула:**
```
SV = EV - PV
```

**Інтерпретація:**
- **SV > 0:** Попереду графіка
- **SV = 0:** За графіком
- **SV < 0:** Поза графіком

---

### 5. Відхилення Вартості (CV)

**Формула:**
```
CV = EV - AC
```

**Інтерпретація:**
- **CV > 0:** Під бюджетом
- **CV = 0:** В межах бюджету
- **CV < 0:** Понад бюджетом

---

## Розрахунок Бюджету

### Загальний Доступний Бюджет

**Формула:**
```
Загальний Доступний Бюджет = PV (Базовий) + Позитивні Транзакції (Доходи)
```

**Компоненти:**
1. **PV Базовий:** Запланована Вартість представляє оригінальний бюджет
2. **Позитивні Транзакції:** Сума всіх документів `Transaction`, де `type === '+'` (дохід)

**Джерело Істини:**
- PV: Розраховується з задач (див. розділ PV)
- Доходи: Колекція `Transaction` (`type: '+'`)

### Залишковий Бюджет

**Формула:**
```
Залишковий Бюджет = (PV + Загальні Додаткові Кошти) - AC
```

Де:
- `Загальні Додаткові Кошти` = Сума позитивних транзакцій (`type: '+'`)

## Адаптивна Гранулярність (Вибірка S-Кривої)

Система використовує 5-рівневу адаптивну систему гранулярності для оптимізації щільності графіка (ціль: 30-60 точок даних).

### Логіка Розрахунку Кроку

На основі тривалості проекту (`тривалістьДнів = кінцеваДата - початковаДата`):

| Тривалість | Крок | Опис |
|------------|------|------|
| < 60 днів | 1 день | Щоденна вибірка |
| < 180 днів | 7 днів | Щотижнева вибірка |
| < 730 днів (2 роки) | 14 днів | Двотyzжнева вибірка |
| < 1825 днів (5 років) | 30 днів | Щомісячна вибірка |
| ≥ 1825 днів | 90 днів | Квартальна вибірка |

### Ін'єкція Ключових Дат

Наступні дати **завжди** включені в точки даних:
1. **Дата Початку Проекту** (`project.createdAt`)
2. **Сьогодні** (поточна дата)
3. **Дедлайн Проекту** (`project.deadline`, якщо встановлено)

### Генерація Точок Даних

1. Генерувати дати, використовуючи розрахований крок
2. Ін'єктувати ключові дати (початок, сьогодні, дедлайн)
3. Сортувати хронологічно
4. Видалити дублікати
5. Розрахувати PV, AC, EV для кожної дати:
   - **PV:** Розраховується для всіх дат (розширюється до майбутнього)
   - **AC & EV:** Розраховується тільки для дат ≤ сьогодні (null для майбутніх дат)

## Оптимізація Продуктивності

### Кешування Знімків

**Мета:** Зменшити час перерахунку для історичних дат.

**Реалізація:**
- Щоденна cron-задача (`dailyEVMJob.js`) розраховує та зберігає знімки
- Структура знімка:
  ```javascript
  {
    date: Date,
    plannedValue: Number,
    actualCost: Number,
    earnedValue: Number
  }
  ```

**Пріоритет Кешу:**
1. Перевірити `project.evmSnapshots` для історичних дат (`date < today`)
2. Якщо знімок існує: Повернути кешоване значення одразу
3. Якщо знімок відсутній або дата - сьогодні/майбутнє: Розрахувати нормально

**Швидкість Попадання в Кеш:** ~95-100% для історичних дат

### Індексація Бази Даних

Оптимізовані індекси для швидших запитів:

- **Task:** `{ projectId: 1, status: 1, updatedAt: -1 }` (для розрахунку EV)
- **Expense:** `{ projectId: 1, createdAt: 1, frequency: 1 }` (для розрахунку AC)
- **Transaction:** `{ projectId: 1, type: 1, date: -1 }` (для розрахунку бюджету)

## API Кінцеві Точки

### Отримати Підсумкову Статистику (Швидке Завантаження)
```
GET /api/projects/:projectId/stats?summary=true
```

Повертає:
- Поточні PV, AC, EV (значення на сьогодні)
- Відхилення (Графік, Вартість)
- Бюджет (Базовий, Додаткові Кошти, Залишок)

**Продуктивність:** ~200-500мс

### Отримати Дані Графіка (Відкладене Завантаження)
```
GET /api/projects/:projectId/stats?chart=true
```

Повертає:
- Масив `evmDataPoints` (для графіка S-Кривої)
- Масив `plannedValueCurve`

**Продуктивність:** ~1-3с (використовує знімки для історичних дат)

### Отримати Повні Дані (Зворотна Сумісність)
```
GET /api/projects/:projectId/stats
```

Повертає і підсумок, і дані графіка.

## Потік Даних

### Потік Розрахунку

1. **Користувач запитує Фінансову Панель**
2. **Frontend робить 2 API виклики:**
   - Виклик 1: `GET /stats?summary=true` (швидко)
   - Виклик 2: `GET /stats?chart=true` (відкладено)

3. **Backend обробляє дані графіка:**
   - Для кожної дати в діапазоні:
     - **Якщо дата < сьогодні:** Спочатку перевірити `project.evmSnapshots`
       - ✅ Попадання в Кеш: Повернути значення знімка
       - ❌ Промах Кешу: Розрахувати з нуля
     - **Якщо дата >= сьогодні:** Завжди розраховувати (немає знімка)

4. **Щоденна Cron Задача:**
   - Запускається о 00:00 UTC щодня
   - Розраховує PV, AC, EV для "вчора"
   - Зберігає в масив `project.evmSnapshots`

## Примітки

- Всі грошові значення зберігаються та розраховуються в базовій валюті проекту
- Дати нормалізуються до початку дня (00:00:00) для послідовних порівнянь
- Майбутні дати мають `AC` та `EV` встановлені в `null` (не розраховуються)
- PV розширюється до майбутніх дат (представляє заплановану роботу)
