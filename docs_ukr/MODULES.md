## 1. Модуль Інформації про Проект

### Призначення
Управляє метаданими проекту, налаштуваннями та конфігурацією.

### Ключові Функції

#### Управління Дедлайном
- **Поле:** `Project.deadline` (Date, nullable)
- **RBAC Перевірка:** Вимагає дозвіл `can_manage_deadline`
- **Валідація:**
  - Дедлайн повинен бути строго після `project.createdAt`
  - Не може дорівнювати або бути раніше дати створення
- **Розташування UI:** Бічна панель інформації про проект
- **Доступ до Редагування:** Тільки користувачі з дозволом `can_manage_deadline`

**Рівні Дозволів:**
- **Власник:** Завжди має дозвіл (через `ALL_PERMISSIONS`)
- **Менеджер Проекту:** Повинен мати `can_manage_deadline` в масиві дозволів
- **Інші Ролі:** Доступ тільки для читання

#### Конфігурація Робочого Графіка
- **Поле:** `Project.workSchedule`
- **Властивості:**
  - `workingDaysPerWeek` (1-7)
  - `daysOffPerWeek` (0-6)
  - `hoursPerDay` (1-24)
- **Валідація:** `workingDaysPerWeek + daysOffPerWeek = 7`
- **RBAC Перевірка:** Вимагає дозвіл `can_manage_work_schedule`
- **Використання:** Використовується для розрахунку денних/годинних ставок з місячних зарплат

#### Члени Проекту
- **Поле:** `Project.members[]`
- **Структура:**
  - `userId` (посилання ObjectId на User)
  - `roles[]` (масив назв ролей)
  - `permissions[]` (масив рядків дозволів)
  - `hourlyRate` (Number)
  - `joinedAt` (Date)
  - `notificationSettings` (Object)

**Система Ролей:**
- Ролі за замовчуванням: `Owner`, `Guest`
- Кастомні ролі: Визначені в `Project.customRoles[]`
- Множинні ролі: Члени можуть мати кілька ролей
- Наслідування дозволів: Дозволи з усіх ролей агрегуються

## 2. Модуль Kanban / Задач

### Призначення
Управляє задачами проекту з інтерфейсом Kanban дошки.

### Ключові Функції

#### Потік Статусів Задач
```
Todo → In Progress → Review → Done
```

#### Властивості Задачі
- `projectId` (посилання ObjectId)
- `title` (String, обов'язково)
- `description` (String)
- `status` (Enum: 'Todo', 'In Progress', 'Review', 'Done')
- `priority` (Enum: 'Low', 'Medium', 'High', 'Critical')
- `complexity` (Enum: 'Low', 'Med', 'High')
- `assignees[]` (посилання ObjectId на User)
- `startDate` (Date)
- `deadline` (Date)
- `estimateHours` (Number, обов'язково, min: 0)
- `plannedValue` (Number, автоматично розраховується)
- `plannedCost` (Number, автоматично розраховується)
- `risk` (Object з probability, impact, auto_score)

#### Інтеграція з Розрахунком EV
- **Завершені Задачі Надходять у EV:**
  - Тільки задачі з `status === 'Done'` вносять внесок у Зароблену Вартість
  - EV = Сума бюджетів задач для завершених задач
  - Бюджет задачі = `estimateHours × Середня Годинна Ставка`
  - Дата завершення = `Task.updatedAt` (коли статус змінився на 'Done')

**Логіка Розрахунку:**
```javascript
// Знайти всі завершені задачі
const completedTasks = await Task.find({
  projectId,
  status: 'Done',
  updatedAt: { $lte: цільоваДата }
});

// Розрахувати EV з завершених задач
let totalEV = 0;
for (const task of completedTasks) {
  const taskBudget = estimateHours × averageHourlyRate;
  totalEV += taskBudget;
}
```

#### Індекси Бази Даних
- `{ projectId: 1, status: 1, updatedAt: -1 }` - Оптимізовано для розрахунку EV

## 3. Модуль Фінансової Панелі

### Призначення
Надає комплексне фінансове відстеження за допомогою управління заробленою вартістю (EVM).

### Ключові Функції

#### Картки Метрик (Швидке Завантаження)
- **Запланована Вартість (PV):** Бюджетна вартість запланованої роботи
- **Фактична Вартість (AC):** Фактична понесена вартість
- **Зароблена Вартість (EV):** Бюджетна вартість виконаної роботи
- **Відхилення Графіка (SV):** `EV - PV`
- **Відхилення Вартості (CV):** `EV - AC`
- **Залишковий Бюджет:** `(PV + Доходи) - AC`

#### Графік S-Кривої (Відкладене Завантаження)
- **Джерело Даних:** Масив `evmDataPoints[]`
- **Адаптивна Гранулярність:** 5-рівнева система кроків (див. EVM_FINANCIAL_LOGIC.md)
- **Ключові Дати:** Завжди включає початок проекту, сьогодні та дедлайн
- **Майбутні Дані:** AC та EV є `null` для майбутніх дат

#### Оптимізація Продуктивності
- **Підсумкова Статистика:** ~200-500мс (швидке завантаження)
- **Дані Графіка:** ~1-3с (використовує знімки для історичних дат)
- **Кешування Знімків:** 95-100% швидкість попадання в кеш для історичних дат

**API Кінцеві Точки:**
- `GET /api/projects/:projectId/stats?summary=true` - Швидкі картки метрик
- `GET /api/projects/:projectId/stats?chart=true` - Дані графіка
- `GET /api/projects/:projectId/stats` - Повні дані (зворотна сумісність)

## 4. Модуль Звіту для Інвесторів

### Призначення
Генерує комплексні фінансові звіти для інвесторів з можливістю експорту PDF.

### Ключові Функції

#### Фільтр Часового Діапазону
- **Опції:**
  - `'all'` - Вся тривалість проекту (від `project.createdAt` до сьогодні)
  - `'month'` - Поточний місяць (від початку місяця до сьогодні)
  - `'year'` - Поточний рік (від початку року до сьогодні)

**API Кінцева Точка:**
```
GET /api/projects/:projectId/reports/investor?range=all|month|year
```

#### Розділи Звіту

1. **Швидкість Витрат (Burn Rate)**
   - Місячна: `Загальний AC / Тривалість Проекту (місяці)`
   - Денна: `Місячна Швидкість Витрат / 30.44`

2. **Резерв (Runway)**
   - Розрахунок: `Залишковий Бюджет / Швидкість Витрат`
   - Статус: `healthy` (>6 місяців), `warning` (3-6 місяців), `critical` (<3 місяці), `infinite` (швидкість витрат = 0)
   - Дата: Розрахована дата, коли закінчаться кошти
   - Контекст Дедлайну: Показує, чи закінчаться кошти до дедлайну проекту

3. **Фінанси**
   - Запланована Загальна: PV (Запланована Вартість)
   - Фактична Загальна: AC (Фактична Вартість)
   - Відхилення: `AC - PV`

4. **Топ Ризики**
   - Топ 3 задачі з найвищим `risk.auto_score`
   - Включає: Назву задачі, оцінку ризику, ймовірність, вплив, опис, статус

5. **Статус Дорожньої Карти**
   - Завершені Задачі: Кількість та відсоток
   - Минув Час: Відсоток тривалості проекту
   - Попереду Графіка: `completedPercentage > timeElapsedPercentage`
   - Валідний Дедлайн: Прапорець, що вказує, чи дедлайн валідний (не за замовчуванням)

6. **Дані Команди** (Тільки для Власника)
   - Розподіл Ролей: Кількість членів на роль
   - Список Членів: Ім'я, email, ролі, місячна зарплата, годинна ставка, денна ставка
   - Загальна Місячна Зарплата: Сума зарплат усіх членів

#### Генерація PDF
- **Технологія:** `html2canvas` + `jsPDF`
- **Процес:**
  1. Відрендерити вміст звіту в HTML
  2. Захопити як зображення за допомогою `html2canvas`
  3. Згенерувати PDF за допомогою `jsPDF`
  4. Завантажити PDF файл

**Frontend Компонент:** `client/src/components/investor-report-modal.tsx`

## 5. Модуль Транзакцій

### Призначення
Управляє фінансовими транзакціями (доходи та витрати) для проектів.

### Модель Транзакції

```javascript
{
  projectId: ObjectId,
  amount: Number,
  type: '+' | '-',  // '+' = Дохід, '-' = Витрата
  source: String,
  date: Date,
  authorId: ObjectId,
  description: String
}
```

### Використання в EVM

#### Транзакції Дохідів (`type: '+'`)
- **Призначення:** Збільшити доступний бюджет
- **Формула:** `Загальний Доступний Бюджет = PV + Сума(Транзакції Дохідів)`
- **Розрахунок:** Сума всіх транзакцій, де `type === '+'`

#### Транзакції Витрат (`type: '-'`)
- **Призначення:** Збільшити Фактичну Вартість
- **Формула:** `AC = Зарплати + Фіксовані Витрати + Сума(Транзакції Витрат)`
- **Розрахунок:** Сума всіх транзакцій, де `type === '-'` та `date <= цільоваДата`

### Індекси Бази Даних
- `{ projectId: 1, type: 1, date: -1 }` - Оптимізовано для розрахунку бюджету

## 6. Модуль Ролей та Дозволів

### Призначення
Управляє контролем доступу на основі ролей (RBAC) для проектів.

### Система Дозволів

#### Доступні Дозволи (`ALL_PERMISSIONS`)
- **Дозволи Перегляду:**
  - `can_view_dashboard`
  - `can_view_tasks`
  - `can_view_risks`
  - `can_view_financial`

- **Дозволи Дій:**
  - `can_create_tasks`
  - `can_edit_tasks`
  - `can_delete_tasks`
  - `can_edit_budget`
  - `can_manage_roles`
  - `can_invite_users`
  - `can_manage_settings`
  - `can_manage_salaries`
  - `can_manage_work_schedule`
  - `can_manage_deadline` ⭐ (Потрібно для редагування дедлайну проекту)
  - `can_delete_project`
  - `can_generate_reports`

- **Дозволи Сповіщень:**
  - `notify_on_financial_risk`
  - `notify_on_task_assignment`
  - `notify_on_role_change`

#### Ролі за Замовчуванням

**Власник:**
- Має ВСІ дозволи (через масив `ALL_PERMISSIONS`)
- Не може бути видалений або змінений
- Завжди має доступ до всіх функцій

**Гість:**
- Нуль дозволів за замовчуванням
- Повинен отримати дозволи від Власника
- Найнижчий рівень ієрархії

#### Кастомні Ролі
- Визначені в `Project.customRoles[]`
- Можуть мати будь-яку назву
- Масив дозволів повинен містити тільки значення з `ALL_PERMISSIONS`
- Ієрархія: Вище за Гість, нижче за Власника

#### Агрегація Дозволів
- Члени можуть мати кілька ролей
- Дозволи з усіх ролей об'єднуються (об'єднання)
- Власник завжди має всі дозволи (обходить перевірки ролей)

## Ключові Інтеграції

### Інтеграція з Системою EVM
- **Задачі → EV:** Завершені задачі надходять у розрахунок Заробленої Вартості
- **Транзакції → Бюджет:** Транзакції доходів збільшують доступний бюджет
- **Транзакції → AC:** Транзакції витрат збільшують Фактичну Вартість
- **Зарплати → AC:** Зарплати членів розраховуються як денні ставки

### Інтеграція з Системою Дозволів
- **Управління Дедлайном:** Вимагає дозвіл `can_manage_deadline`
- **Робочий Графік:** Вимагає дозвіл `can_manage_work_schedule`
- **Фінансовий Перегляд:** Вимагає дозвіл `can_view_financial`
- **Генерація Звітів:** Вимагає дозвіл `can_generate_reports`

## Оптимізації Продуктивності

1. **Кешування Знімків:** Історичні значення EVM кешовані в `project.evmSnapshots`
2. **Індексація Бази Даних:** Оптимізовані індекси для розрахунків EV, AC та бюджету
3. **Розділення API:** Підсумкова статистика та дані графіка завантажуються окремо
4. **Адаптивна Гранулярність:** Розумна вибірка для S-Кривої (30-60 точок даних)

## Скрипти Міграції

### Очищення Застарілих Дозволів
```bash
npm run cleanup:permissions
```
Видаляє `can_track_time` та інші невалідні дозволи з бази даних.

### Виправлення Дозволів Дедлайну
```bash
npm run fix:deadline-permissions
```
Додає `can_manage_deadline` до ролей Власника та Менеджера Проекту.
