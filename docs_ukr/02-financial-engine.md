# Фінансовий Движок (EVM)

## Огляд

**Фінансовий Движок** в KBM Logic v3.0 реалізує **Управління Заробленою Вартістю (EVM)** з логікою нарахування, що враховує розклад. Всі фінансові розрахунки враховують робочий розклад проекту (робочі дні, години на день) та використовують історичні ставки ролей для точних часових розрахунків.

## Основні Концепції

### PV (Запланована Вартість) - АВТОМАТИЗОВАНО

**Запланована Вартість** представляє затверджений бюджет на роботу, заплановану до завершення на певну дату. В v3.0, PV **повністю автоматизована** та розраховується з задач.

#### Формула

```
PV = Σ (Робочі Години Задачі × Годинна Ставка Ролі)
```

Де:
- **Робочі Години Задачі** = Розраховується на основі Робочого Розкладу Проекту
  - Якщо задача має `startDate` та `deadline`: `Робочі Дні × Години на День`
  - Інакше: Використовує `task.estimateHours` безпосередньо
- **Годинна Ставка Ролі** = Похідна від Місячної Зарплати Ролі
  - Формула: `Місячна Ставка / (Робочі Дні на Місяць × Години на День)`
  - За замовчуванням: 21 робочий день на місяць, 8 годин на день

### AC (Фактична Вартість) - Нарахування з Урахуванням Розкладу

**Фактична Вартість** представляє реально витрачені гроші. В v3.0, AC використовує **нарахування з урахуванням розкладу** - витрати нараховуються тільки на робочі дні, визначені робочим розкладом проекту.

#### Формула

```
AC = Витрати на Зарплати + Фіксовані Витрати + Негативні Транзакції
```

#### Витрати на Зарплати (з Урахуванням Розкладу)

```
Денна Ставка = Місячна Зарплата / 21 (робочі дні на місяць)
AC (на день) = Денна Ставка × Відсоток Використання
```

**Ключові Моменти:**
- Витрати **нараховуються тільки на робочі дні** (Пн-Пт за замовчуванням)
- Вихідні та свята виключаються
- Відсоток використання враховує неповний робочий день
- Історичні ставки зберігаються через `salaryHistory`

### Транзакції - Подвійне Відмічання Часу

Транзакції використовують **подвійне відмічання часу** для підтримки ретроактивних фінансових записів:

#### Поля

- **`createdAt`** (автоматичне) - Коли транзакція була введена в систему
- **`effectiveDate`** (надається користувачем) - Коли транзакція повинна впливати на фінансові розрахунки
- **`date`** (застаріле, незмінне) - Встановлюється в `effectiveDate` для зворотної сумісності

### Машина Часу (Регенератор Снапшотів)

Коли створюється транзакція з ретроактивною `effectiveDate`, система запускає **Регенератор Снапшотів** для перерахунку історичних даних EVM.

## Фінансові Метрики

### Відхилення Розкладу (SV)

**Формула:**
```
SV = EV - PV
```

**Інтерпретація:**
- **SV > 0:** Попереду графіка
- **SV < 0:** Поза графіком
- **SV = 0:** За графіком

### Відхилення Вартості (CV)

**Формула:**
```
CV = EV - AC
```

**Інтерпретація:**
- **CV > 0:** Під бюджетом (економія)
- **CV < 0:** Понад бюджетом
- **CV = 0:** За бюджетом

### Швидкість Витрат (Burn Rate)

**Формула:**
```
Швидкість Витрат = Загальні Фактичні Витрати / Тривалість Проекту (в місяцях)
```

### Runway

**Формула:**
```
Runway = Залишковий Бюджет / Швидкість Витрат
```

**Результат:** Кількість місяців до вичерпання бюджету.

## Розрахунок Бюджету

### Загальний Доступний Бюджет

```
Загальний Бюджет = Базовий PV + Транзакції Доходів
```

Де:
- **Базовий PV** = Початкова запланована вартість з задач
- **Транзакції Доходів** = Транзакції з `type: '+'`

### Залишковий Бюджет

```
Залишковий Бюджет = Загальний Бюджет - Фактична Вартість (AC)
```

## Деталі Реалізації

### EVM Движок (`server/services/evmEngine.js`)

Ключові функції:
- `calculatePV(project, date, startDate)` - Розрахувати Заплановану Вартість
- `calculateAC(project, date, startDate)` - Розрахувати Фактичну Вартість
- `calculateEV(project, date, startDate)` - Розрахувати Зароблену Вартість
- `resolveRoleRateForDate(project, roleName, targetDate)` - Отримати історичну ставку ролі

### Система Снапшотів

Снапшоти зберігаються в `project.evmSnapshots`:

```javascript
{
  date: Date,
  PV: Number,
  AC: Number,
  EV: Number
}
```

Снапшоти:
- Генеруються щодня через cron job (`dailyEVMJob.js`)
- Регенеруються коли створюються ретроактивні транзакції
- Використовуються для історичних даних графіків

## Найкращі Практики

1. **Встановіть Робочий Розклад Ранно:** Налаштуйте `workSchedule` перед створенням задач
2. **Використовуйте Ефективні Дати:** Завжди встановлюйте `effectiveDate` для транзакцій
3. **Моніторьте Здоров'я Бюджету:** Перевіряйте відсоток здоров'я бюджету регулярно
4. **Перевіряйте Снапшоти:** Перевіряйте точність історичних даних після ретроактивних змін
5. **Зміни Ставок Ролей:** Оновлюйте ставки ролей через Налаштування → Ролі для збереження історії
