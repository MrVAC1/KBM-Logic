# Задачі та Робочий Процес

## Огляд

Система **Управління Задачами** в KBM Logic v3.0 надає робочий процес у стилі Kanban з функціональністю drag-and-drop, розрахунками тривалості з урахуванням розкладу та інтегрованим відстеженням часу.

## Kanban Дошка

### Структура Дошки

Kanban дошка складається з **4 колонок**, що представляють статус задач:

1. **Todo** - Новостворені задачі, ще не розпочаті
2. **In Progress** - Задачі, над якими зараз працюють
3. **Review** - Задачі, завершені та очікують перевірки/схвалення
4. **Done** - Завершені задачі (вносять внесок у розрахунок EV)

### Drag-and-Drop

Задачі можна переміщувати між колонками через drag-and-drop:

- **Візуальний Зворотний Зв'язок:** Картка задачі слідує за курсором під час перетягування
- **Оновлення Статусу:** Скидання задачі оновлює її поле `status`
- **Автозбереження:** Зміни зберігаються негайно через API виклик
- **Перевірка Дозволів:** Вимагає дозвіл `can_edit_tasks`

## Логіка Задач

### Розрахунок Тривалості

Тривалість задачі розраховується на основі **Робочого Розкладу Проекту**:

#### З Датою Початку та Дедлайном

Якщо встановлені обидва `startDate` та `deadline`:

```
Тривалість (години) = Робочі Дні × Години на День
```

Де:
- **Робочі Дні** = Кількість робочих днів між `startDate` та `deadline` (включно)
- **Години на День** = `project.workSchedule.hoursPerDay` (за замовчуванням: 8)
- **Виключення Вихідних** = Рахуються тільки дні в `project.workSchedule.workingDays`

#### Без Дат

Якщо `startDate` або `deadline` відсутні:

```
Тривалість (години) = estimateHours
```

Використовує поле `estimateHours` безпосередньо.

### Розрахунок Запланованої Вартості

**Запланована Вартість** (та **Запланована Вартість**) автоматично розраховується при створенні або оновленні задачі:

```
Запланована Вартість = Тривалість (години) × Середня Годинна Ставка
```

Де:
- **Тривалість** = Розраховується як вище (робочі дні × години на день)
- **Середня Годинна Ставка** = Середнє значення годинних ставок ролей виконавців

## Відстеження Часу

### Старт/Стоп Таймер

Задачі підтримують **відстеження часу** через функціональність старт/стоп таймера:

**UI:** Натисніть кнопку "Start Timer" на картці задачі

**Процес:**
1. Користувач натискає "Start Timer"
2. Система створює запис `timeLog` з `startTime = зараз`
3. Таймер працює до натискання "Stop Timer"
4. Система встановлює `endTime = зараз` та розраховує `duration` (секунди)

### Множинні Журнали Часу

Задача може мати **кілька журналів часу**:
- Різні користувачі можуть відстежувати час на одній задачі
- Кожен користувач може мати один активний таймер одночасно
- Історичні журнали зберігаються для звітності

## Життєвий Цикл Задачі

### Створення

1. **Дія Користувача:** Натиснути кнопку "Створити Задачу"
2. **Обов'язкові Поля:**
   - Назва
   - Оцінка Годин
   - Виконавці (опціонально)
   - Дата Початку (опціонально)
   - Дедлайн (опціонально)
3. **Автоматичні Розрахунки:**
   - Запланована Вартість (з тривалості × ставок)
   - Оцінка Ризику (початковий розрахунок)
4. **Сповіщення:** Призначені користувачі отримують сповіщення

### Завершення

Коли задача переходить у статус **Done**:

1. **Внесок у EV:** `plannedValue` задачі додається до розрахунку EV
2. **Дата Завершення:** Мітка часу `updatedAt` позначає завершення
3. **Сповіщення:** Призначені користувачі отримують сповіщення про завершення
4. **Оновлення Ризику:** Оцінка ризику може зменшитися (задача більше не під ризиком)

## Найкращі Практики Робочого Процесу

1. **Встановіть Реалістичні Оцінки:** Використовуйте точні `estimateHours` для фінансового планування
2. **Використовуйте Дати Початку:** Встановіть `startDate` та `deadline` для точного розрахунку тривалості
3. **Призначайте Ролі:** Призначайте задачі користувачам з відповідними ролями
4. **Відстежуйте Час:** Використовуйте функціональність таймера для вимірювання фактичних vs. оцінених годин
5. **Оновлюйте Статус:** Тримайте статус задачі актуальним для точної видимості робочого процесу
