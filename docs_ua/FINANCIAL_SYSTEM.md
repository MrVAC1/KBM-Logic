# Фінансова Система та Управління Заробленою Вартістю (EVM)

## Огляд

Фінансова Система реалізує методологію Управління Заробленою Вартістю (EVM) для відстеження продуктивності проєкту, бюджету та графіка. Вона надає актуальні інсайти про стан проєкту через три ключові метрики: Запланована Вартість (PV), Фактична Вартість (AC), та Зароблена Вартість (EV).

---

## Основні Концепції

### Управління Заробленою Вартістю (EVM)

EVM - це техніка управління проєктами, яка інтегрує метрики обсягу, графіка та вартості для надання комплексного погляду на продуктивність проєкту.

#### Три Ключові Метрики:

1. **Запланована Вартість (PV)** - "План"
   - Бюджетна вартість роботи, запланованої до завершення на певну дату
   - Представляє базову бюджетну криву (S-крива)
   - Відображається як пунктирна сіро-блакитна лінія на графіку

2. **Фактична Вартість (AC)** - "Витрати"
   - Фактична вартість, понесена за виконану роботу на певну дату
   - Включає щоденні витрати на зарплати та витрати проєкту
   - Відображається як суцільна червоно-помаранчева лінія на графіку

3. **Зароблена Вартість (EV)** - "Вартість"
   - Бюджетна вартість фактично виконаної роботи на певну дату
   - Збільшується лише коли задачі позначені як "Виконано"
   - Відображається як суцільна яскраво-зелена лінія на графіку

### Індикатори Відхилень

#### Відхилення Графіка (SV)
- **Формула:** `SV = EV - PV`
- **Інтерпретація:**
  - **Позитивне (Зелене):** Попереду графіка
  - **Негативне (Червоне):** Відставання від графіка
  - **Нуль:** В межах графіка

#### Відхилення Вартості (CV)
- **Формула:** `CV = EV - AC`
- **Інтерпретація:**
  - **Позитивне (Зелене):** Нижче бюджету
  - **Негативне (Червоне):** Перевищення бюджету
  - **Нуль:** В межах бюджету

## Як Це Працює

### 1. Розрахунок Запланованої Вартості (PV)

**Алгоритм:**
- Перебирає всі задачі в проєкті
- Для кожної задачі:
  - Обчислює бюджет задачі = `Оцінка годин × Середня погодинна ставка виконавців`
  - Якщо дата знаходиться між датою початку та дедлайном задачі:
    - Обчислює лінійну щоденну частку: `Бюджет задачі / Днів тривалості`
    - Додає накопичену частку до PV
  - Якщо дата після дедлайну:
    - Додає повний бюджет задачі до PV

**Розрахунок Погодинної Ставки:**
```
Погодинна Ставка = Місячна Зарплата / (Робочих днів на місяць × Годин на день)
Робочих днів на місяць = (Робочих днів на тиждень / 7) × 30.44
```

### 2. Розрахунок Фактичної Вартості (AC)

**Автоматичний Щоденний Розрахунок:**
- Запускається щодня о 00:00 UTC через cron job
- Обчислює щоденні витрати з:
  - **Зарплати:** Сума щоденних ставок всіх активних членів команди
  - **Витрати:** Щоденний еквівалент повторюваних витрат (щоденні, тижневі, місячні, річні)

**Розрахунок Щоденної Ставки:**
```
Щоденна Ставка = Місячна Зарплата / Робочих днів на місяць
```

**Конвертація Частоти Витрат:**
- **Щоденні:** Повна сума на день
- **Тижневі:** Сума / 7
- **Місячні:** Сума / 30.44
- **Річні:** Сума / 365

**Збереження:**
- Щоденні знімки зберігаються в `project.evmSnapshots[]`
- Накопичена AC зберігається в `project.cumulativeActualCost`

### 3. Розрахунок Заробленої Вартості (EV)

**Алгоритм:**
- Знаходить всі задачі зі `status === 'Done'`
- Фільтрує задачі, завершені на або до цільової дати
- Сумує бюджети задач (той самий розрахунок, що й PV) для завершених задач

**Ключове Правило:**
- EV збільшується лише коли задача **повністю завершена** (статус = 'Done')
- Часткове виконання не вносить внесок у EV

## Конфігурація Робочого Графіка

Кожен проєкт має конфігурований робочий графік, який впливає на всі розрахунки:

- **Робочих днів на тиждень:** За замовчуванням 5 (Понеділок-П'ятниця)
- **Вихідних днів на тиждень:** За замовчуванням 2 (Субота-Неділя)
- **Годин на день:** За замовчуванням 8

Ці налаштування можна змінити в **Інформація проєкту → Робочий Графік** (потрібен дозвіл `can_manage_work_schedule`).

## Зарплати Користувачів

### Встановлення Зарплат
1. Перейдіть до **Налаштування → Витрати → Зарплати Учасників**
2. Введіть місячну зарплату для кожного члена команди
3. Потрібен дозвіл `can_manage_salaries`

### Вплив на Розрахунки
- Зарплати використовуються для обчислення погодинних та щоденних ставок
- Лише члени з `monthlySalary > 0` вносять внесок у AC
- Бюджети задач обчислюються з використанням зарплат виконавців

---

## Витрати Проєкту

### Додавання Витрат
1. Перейдіть до **Налаштування → Витрати → Інші Витрати Проєкту**
2. Натисніть "Додати Витрату"
3. Введіть:
   - Назву витрати
   - Суму
   - Частоту (щоденні, тижневі, місячні, річні)

### Вплив Витрат
- Витрати автоматично включаються в щоденні розрахунки AC
- Конвертуються в щоденний еквівалент залежно від частоти
- Можуть бути відредаговані або видалені після створення

## S-Крива Графік

Фінансова Панель відображає S-кривий графік, що показує PV, AC та EV з часом.

### Інтерпретація Графіка:

1. **Лінія PV (Пунктирна Сіра):**
   - Повинна слідувати плавній S-кривій
   - Представляє базову лінію запланованих витрат

2. **Лінія AC (Суцільна Червона):**
   - Показує фактично витрачені кошти
   - В ідеалі повинна близько слідувати лінії PV
   - Якщо вище PV: Витрати швидше, ніж заплановано
   - Якщо нижче PV: Витрати повільніше, ніж заплановано

3. **Лінія EV (Суцільна Зелена):**
   - Показує вартість виконаної роботи
   - В ідеалі повинна відповідати або перевищувати PV
   - Якщо нижче PV: Відставання від графіка
   - Якщо вище PV: Попереду графіка

### Ідеальний Сценарій:
- **EV = PV:** В межах графіка
- **EV = AC:** В межах бюджету
- **EV > PV:** Попереду графіка
- **EV > AC:** Нижче бюджету

## Cron Job

Щоденний розрахунок EVM запускається автоматично через `node-cron`:
- **Графік:** Кожен день о 00:00 UTC
- **Функція:** `calculateDailyActualCost()`
- **Дія:** Обчислює та зберігає щоденні знімки AC для всіх активних проєктів

## Найкращі Практики

1. **Встановіть Точні Зарплати:** Переконайтеся, що всі члени команди мають правильні місячні зарплати
2. **Визначте Робочий Графік:** Налаштуйте реалістичні робочі дні/години для проєкту
3. **Оцініть Години Задач:** Надайте точну `estimateHours` при створенні задач
4. **Встановіть Дати Задач:** Завжди вказуйте `startDate` та `deadline` для задач
5. **Моніторте Регулярно:** Перевіряйте індикатори Відхилення Графіка та Вартості часто
6. **Оновлюйте Статус Задач:** Позначайте задачі як "Виконано", коли робота завершена, щоб оновити EV

---

## Вирішення Проблем

### EV Не Збільшується
- **Причина:** Задачі не позначені як "Виконано"
- **Рішення:** Оновіть статус задачі на "Done" після завершення роботи

### AC Занадто Високий/Низький
- **Причина:** Відсутні або неправильні зарплати
- **Рішення:** Перевірте, що всі члени команди мають правильні місячні зарплати

### PV Не Розраховується
- **Причина:** Задачі не мають `estimateHours`, `startDate` або `deadline`
- **Рішення:** Переконайтеся, що всі задачі мають заповнені обов'язкові поля

### Відхилення Графіка Завжди Негативне
- **Причина:** Задачі займають більше часу, ніж оцінено
- **Рішення:** Перевірте оцінки задач та дедлайни, розгляньте оновлення оцінок

## Технічні Деталі

### Схема Бази Даних

**Модель Проєкту:**
```javascript
{
  workSchedule: {
    workingDaysPerWeek: Number, // За замовчуванням: 5
    daysOffPerWeek: Number,      // За замовчуванням: 2
    hoursPerDay: Number          // За замовчуванням: 8
  },
  evmSnapshots: [{
    date: Date,
    plannedValue: Number,
    actualCost: Number,
    earnedValue: Number
  }],
  cumulativeActualCost: Number
}
```

**Модель Користувача:**
```javascript
{
  monthlySalary: Number // За замовчуванням: 0
}
```

**Модель Задачі:**
```javascript
{
  estimateHours: Number,    // Обов'язково
  startDate: Date,
  deadline: Date,
  status: String,           // 'Todo', 'In Progress', 'Review', 'Done'
  assignees: [ObjectId]
}
```

## Підсумок

Фінансова Система надає комплексне відстеження продуктивності проєкту через метрики EVM. Моніторячи PV, AC та EV, менеджери проєктів можуть:

- Виявляти затримки графіка рано
- Виявляти перевищення бюджету
- Приймати рішення на основі даних
- Покращувати точність планування проєктів

Регулярний моніторинг та точний ввід даних є необхідними для надійного аналізу EVM.
